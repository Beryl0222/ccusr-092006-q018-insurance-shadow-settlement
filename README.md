# 医保目录影子结算后端

首批国家医疗服务项目目录正式启用前，经办机构用本系统对**同一批脱敏历史费用**按国家项目（候选侧）与本地旧项目（现行侧）各算一次，量化编码缺失、组合规则冲突与支付范围变化；演练全程只读历史、只写影子，**不触碰原支付状态，也不产生任何发布动作**。

零运行时依赖，仅使用 Node.js 内置能力（ESM、`node:test`、`node:crypto`）。

## 能力对照

| 要求 | 实现 |
| --- | --- |
| 冻结目录版本、地区映射、支付限制、样例费率 | `src/freeze.js`：内容哈希为身份、对象冻结、版本时间线不允许区间重叠 |
| 对脱敏历史事件按就医发生时点重放 | `src/service.js`：候选包固定哈希；现行侧对每条事件按其 `service_date` 经 `FreezeRegistry.effectiveAt` 选取当时版本 |
| 现行结果与候选结果分别保存 | `COMPARISON_PRODUCED` 事件同时保存 `incumbent` / `candidate` 两套行级结果与合计 |
| 编码缺失 / 组合规则冲突 / 支付范围变化 | `src/evaluate.js` 输出三类差异，**纯样例费率金额差不计为支付范围变化**；每条差异附 `rule_basis`（冻结快照哈希 + 规则号） |
| 任务分片、暂停、恢复 | 按 `claim_id` 内容哈希确定性分片；检查点游标、暂停/恢复事件；支持从事件日志跨进程重建后续跑 |
| 同一事件重复进入只保留一次有效比较 | 接入时 `claim_hash` 幂等、内容碰撞拒绝；比较按"事件+全部冻结依赖"计算幂等键，依赖未变则跳过，依赖变化时新事件经 `supersedes_event_id` 取代旧比较，日志全程可追溯 |
| 专家补充映射后仅重算受影响集合 | `MAPPING_REVISED` 记录 `changed_local_codes`（缺省自动对比新旧条目），增量作业范围 = 该地区费用行命中变动编码集的事件；未受影响的旧比较凭"变动编码不相交"证明可结转 |
| 差异从汇总下钻到规则依据 | `src/diffs.js`：`diffSummary`（汇总，可按候选版本/地区过滤）→ `drillDown(kind)`（分类明细）→ `diffDetail(claimId)`（单事件双侧结果与每条差异的规则依据） |
| 抽样复核门槛 | `src/release.js`：基于内容哈希的确定性抽样（可独立复算）；复核结论 MATCH/MISMATCH/DEFER 只写一次、不可改；一致率 = MATCH/(MATCH+MISMATCH)，须无待复核/搁置 |
| 地区签署门槛 | 签署绑定"候选目录哈希 + 当前映射修订号"；映射再修订后旧签署自动失效，须重算后重新签署 |
| 发布资格 | 五道闸门（抽样合规、复核一致率、结果时效性、无编码缺失、全部必需地区签署）全部通过才记录 `QUALIFIED`；**只记录判定，系统无真实发布出口** |
| 候选目录、患者标识、内部费率留在获准环境 | `src/environment.js`：获准环境白名单 + 落盘根目录圈定；真实结算/患者查询汇槽硬编码禁入；所有事件带 `data_scope=SHADOW` |
| 影子数据不得误入真实结算或患者查询 | 存储构造与每次追加都经边界校验；对外导出患者令牌经带盐哈希假名化（`ext-…`），费率字段与费率表内容整体剥离 |

## 目录

- `src/`
  - `insurance_shadow_settlement.js`：事件词汇、信封校验、历史事件脱敏白名单与 PII 模式拦截
  - `freeze.js`：内容哈希、不可变冻结对象与按时点选取的注册表
  - `evaluate.js`：双侧重放评估与带规则依据的三分类差异
  - `store.js`：只追加事件日志 + 状态归约（去重、有效比较、作业游标、签署/复核状态）
  - `service.js`：冻结登记、接入、映射修订、分片/暂停/恢复/增量作业编排
  - `diffs.js`：汇总 → 分类 → 单事件规则依据三级下钻
  - `release.js`：确定性抽样、复核、地区签署、发布资格判定
  - `environment.js`：获准环境、汇槽硬隔离、路径圈定、合规导出
  - `index.js`：公共出口
- `examples/`：完全虚构的两地区演练夹具与端到端演示
- `data/sample.json`：格式核对样例
- `tests/`：25 项契约/工作流/门槛/边界测试

## 本地核对与演示

```bash
npm test     # 25 项全绿
npm run demo # 端到端演练（冻结→重放暂停恢复→下钻→增量重算→门槛→合规导出）
```

## 关键事件流

```
CATALOG_FROZEN ─┐
CLAIM_INGESTED ─┤
MAPPING_REVISED ┤   REPLAY_STARTED → REPLAY_CHECKPOINT* → (REPLAY_PAUSED → REPLAY_RESUMED)? → REPLAY_COMPLETED
                └─► COMPARISON_PRODUCED（每事件一条有效，旧版以 supersedes_event_id 链挂）
                         │
                         ▼
              SAMPLE_DRAWN → RECHECK_RECORDED* → REGION_SIGNED* → RELEASE_QUALIFIED（仅资格判定）
```

## 设计要点

1. **事件溯源，原地不改**：目录/映射的每次变化都是带内容哈希的新快照；比较被取代时旧事件保留，可审计、可重放。
2. **依赖显式化**：每条比较记录双侧六个冻结哈希（目录/限制/费率）+ 映射哈希，构成幂等键；映射修订后哪些事件必须重算、哪些可结转均可证明。
3. **演练与真实业务物理隔离**：影子存储只允许落在获准环境圈定目录，只允许写影子汇槽；导出走假名化与费率剥离。系统不包含任何真实结算或患者查询的客户端代码。
4. **发布资格是判定不是动作**：即使全部门槛通过，也仅追加 `RELEASE_QUALIFIED=QUALIFIED` 记录；是否发布由系统外的正式流程决定。
